ONE RENDERER / MODEL + SCHEMA + JSON

A form from a definition.

The explicit booking remains the teaching example. This small dynamic version uses the same renderer as Describe a form.

This example supports flat string fields: text, email, textarea and select. The JSON defines the controls; the Angular schema defines validation. Values and submissions stay on this device.

Three inputs

{{ usage }}
UI definition · JSON
{{ definition | json }}
Initial model · JSON
{{ initialValues | json }}

The schema is in dynamic-example.ts. It requires name, email, city and topic, and validates email. UI required labels should match that schema. Configuration is fixed for each mounted form; replacing the form creates a fresh draft.
